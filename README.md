# ggwt
README - Прогноз почасовой выработки ВЭС (итоговая точность 7.99%)
========================================================================

Общее описание
--------------
Задача: предсказать почасовую выработку ВЭС (целевая переменная 
"Выработка. Результирующий расчет") на основе метеорологических 
и эксплуатационных данных.

Данные:
- train_dataset.csv – обучающая выборка с целевой переменной.
- valid_features.csv – валидационная выборка (только признаки), 
  для которой нужно сформировать solverdata.csv.

Особенности:
- 26 турбин Siemens Gamesa G132 по 3.465 МВт (уст. мощность 90.09 МВт).
- Высота оси ротора: 84 метра.
- Направление ветра хранится в нормированном виде [0, 1] (доля от 360°).

Итоговая точность на платформе (автотест): 7.99%
Метрика: средняя абсолютная ошибка в % от установленной мощности.

----------------------------------------------------------------------
1. Загрузка исходных данных
----------------------------------------------------------------------
train = pd.read_csv('train_dataset.csv')
valid = pd.read_csv('valid_features.csv')

- train сортируется по времени для корректной работы лаговых признаков.
- valid НЕ сортируется (сохраняется исходный порядок строк).

----------------------------------------------------------------------
2. Внешние данные реанализа ERA5
----------------------------------------------------------------------
Для улучшения модели используются данные реанализа ERA5 (фактическая 
погода задним числом), загружаемые через Open-Meteo Archive API.

Почему это помогает:
- Исходный train содержит прогноз погоды, а не факт.
- ERA5 даёт наилучшую оценку реальных условий за те же даты.
- ERA5 загружается и для train, и для valid (даты valid уже прошли),
  что устраняет ковариативный сдвиг между обучением и тестом.

----------------------------------------------------------------------
3. Интерполяция на высоту ротора 84 м
----------------------------------------------------------------------
Исходные данные содержат ветер на высотах 10, 80, 120, 180 м.
Высота оси ротора – 84 м, поэтому выполняется интерполяция:

- Скорость ветра: по степенному закону V₂ = V₁·(h₂/h₁)^α, где α 
  определяется по уровням 80 и 120 м.
- Направление: линейная интерполяция компонент sin/cos.
- Температура: линейная интерполяция между 80 и 120 м (или стандартный
  градиент -0.65°C/100 м).

----------------------------------------------------------------------
4. Генерация признаков (Feature Engineering)
----------------------------------------------------------------------
Все признаки создаются в функциях add_base_features (для исходных 
данных) и process_era5 (для ERA5).

4.1 Временные признаки
  - dayofyear, dayofweek, week (номер недели по ISO)
  - hour_sin, hour_cos
  - month_sin, month_cos
  - doy_sin, doy_cos (день года циклически)

4.2 Статические признаки погоды
  - Квадрат и куб скорости на 80 м и 120 м
  - wind_shear = wind_speed_120m - wind_speed_10m
  - gust_ratio = wind_gusts_10m / (wind_speed_10m + 0.1)
  - wind_avg = (wind_speed_80m + wind_speed_120m) / 2

4.3 Признаки на интерполированной высоте 84 м
  - ws84_cubed – куб скорости на 84 м
  - u84, v84 – компоненты ветра (непрерывное представление направления)
  - air_density – плотность воздуха (ρ = P/(R·T))
  - wind_power_density = 0.5 · ρ · V³
  - shear_120_84, shear_84_10 – сдвиги ветра
  - theory_power_total – теоретическая мощность станции:
      * 0, если V < 3 м/с
      * 90.09·((V-3)/(10.3-3))³, если 3 ≤ V < 10.3 м/с
      * 90.09, если 10.3 ≤ V ≤ 25 м/с
      * 0, если V > 25 м/с

4.4 Лаговые признаки (инерция атмосферы)
  - ws84_lag1, ws84_lag2, ws84_lag3 – скорость на 84 м 1, 2, 3 часа назад
  - wd84_lag1_sin, wd84_lag1_cos и аналогично для lag2, lag3 – 
    направление в виде sin/cos с лагами
  * После создания лагов первые 3 строки train удаляются, в valid 
    пропуски заполняются медианой из train.

4.5 Скользящие статистики за 6 часов
  - ws84_rolling_min_6h, ws84_rolling_max_6h, ws84_rolling_std_6h

4.6 Обработка ремонтов
  - Исходный признак "Кол-во_ВЭУ_в_ремонте" неточен (плановый).
  - Создаются:
      * repair_ma6 – скользящее среднее за 6 часов
      * has_repair – бинарный флаг наличия ремонта
      * turbines_available = 26 - repair_count
      * available_ratio = turbines_available / 26
  - Исходная колонка исключается из признаков.

----------------------------------------------------------------------
5. Моделирование
----------------------------------------------------------------------
Используется ансамбль трёх моделей с подбором весов:

5.1 LightGBM
  - Гиперпараметры подбираются Optuna (30 итераций, 3-фолдовая 
    временная кросс-валидация).
  - Бленд 5 сидов для стабильности (усреднение прогнозов).
  - Итоговое число итераций определяется по ранней остановке на holdout.

5.2 Random Forest
  - n_estimators=100, max_depth=8.

5.3 CatBoost
  - iterations=500, learning_rate=0.05, depth=6.

5.4 Подбор весов ансамбля
  - Для каждого года в данных (2023, 2024, 2025) выполняется holdout: 
    модели обучаются на остальных годах, подбираются веса.
  - Итоговые веса усредняются по всем годам.
  - Обычно LightGBM получает вес ~0, RF ~0.4, CatBoost ~0.6.

----------------------------------------------------------------------
6. Защита прогноза по доступной мощности
----------------------------------------------------------------------
- Если turbines_available ≤ 0, прогноз обнуляется.
- Прогноз ограничивается сверху: CAPACITY * available_ratio.

----------------------------------------------------------------------
7. Валидация и метрики
----------------------------------------------------------------------
- Кросс-валидация для подбора гиперпараметров LightGBM: TimeSeriesSplit(3).
- Подбор весов: поочерёдный holdout по годам с усреднением.
- Финальный прогноз сохраняется в solverdata.csv (колонка "выработка").

----------------------------------------------------------------------
8. Инструкция по запуску
----------------------------------------------------------------------
Зависимости:
  pip install pandas numpy requests lightgbm catboost scikit-learn optuna

Запуск:
  1. Поместите train_dataset.csv и valid_features.csv в папку со скриптом.
  2. Запустите скрипт.
  3. Дождитесь завершения (10–30 минут, зависит от CPU).
  4. Загрузите solverdata.csv на платформу.

Примечание: при первом запуске скрипт загружает данные ERA5 через 
API – это может занять несколько минут.

----------------------------------------------------------------------
9. Ключевые факторы успеха
----------------------------------------------------------------------
1. Использование ERA5 (реанализ) и для train, и для valid – главный 
   источник улучшения (с 9.11% до 8.02%).
2. Интерполяция погоды на точную высоту ротора 84 м.
3. Умная обработка ремонтов (сглаживание + флаг).
4. Optuna для подбора гиперпараметров LightGBM (с 8.02% до 7.99%).
5. Ансамбль с усреднением весов по годам для стабильности.

----------------------------------------------------------------------
10. Итоговый результат
----------------------------------------------------------------------
Ошибка на автотесте: 7.99%
Средняя абсолютная ошибка: ≈7.2 МВт при установленной мощности 90.09 МВт.
